# Task Tracker

## О проекте

Task Tracker помогает студенту вести личные задачи. Пользователь добавляет задачу, указывает срок, меняет статус и находит просроченные записи.

## Запуск

Из корня скачанного проекта:

```bash
cd frontend
npm ci
npm run dev
```

После запуска открыть адрес, указанный Vite в терминале.

## Проверка сборки

Остановите dev-сервер через `Ctrl+C`. Выполните в папке `frontend`:

```bash
npm run build
npm run preview
```

## Что работает сейчас

* общий layout с навигацией (React Router) и заметкой о временном хранении данных;
* общий список задач в состоянии `App` (`useState`); начальные данные берутся из `data/tasks.ts`;
* **создание** задачи (`/tasks/new`), **просмотр** (`/tasks/:id`), **редактирование** (`/tasks/:id/edit`) и **удаление** с подтверждением (`window.confirm`);
* одна переиспользуемая форма `TaskForm` с отдельным черновиком: «Отмена» ничего не сохраняет;
* проверка ввода: название 3–100 символов (пробелы обрезаются), обязательный срок; предметное правило — у задачи со статусом «Готово» должно быть описание результата (просроченный срок допустим);
* фильтр списка по статусу и кнопка «Сбросить фильтр»; различаются пустой список и отсутствие совпадений;
* страницы для неизвестного адреса и отсутствующей задачи;
* строгая проверка типов TypeScript (`strict`) и production-сборка.

## Доступные действия

| Действие | Где |
|---|---|
| Создать задачу | «Создать» в навигации или «Добавить задачу» |
| Открыть карточку | клик по названию в списке |
| Изменить задачу | «Редактировать» на странице задачи |
| Удалить задачу | «Удалить» на странице задачи (с подтверждением) |
| Отфильтровать по статусу | выпадающий список над списком, «Сбросить фильтр» |

## Адреса страниц

| Адрес | Страница |
|---|---|
| `/` | перенаправление на `/tasks` |
| `/tasks` | список задач с фильтром |
| `/tasks/new` | создание задачи |
| `/tasks/:id` | подробности задачи (например, `/tasks/t1`) |
| `/tasks/:id/edit` | редактирование задачи |
| любой другой | «Страница не найдена» |

## Ограничение: данные только в памяти

Список живёт в состоянии компонента `App`. Внутренние переходы между страницами изменения сохраняют, но **после обновления страницы или перезапуска приложения возвращаются демонстрационные записи** из `frontend/src/data/tasks.ts`. Постоянное хранение (Supabase) будет добавлено в следующих работах; `localStorage` не используется.

## Текущие ограничения

Отсутствуют Supabase, авторизация и Node API; данные не сохраняются между перезагрузками.
