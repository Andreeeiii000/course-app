# Task Tracker

## О проекте

Task Tracker помогает студенту вести личные задачи. Пользователь добавляет задачу, указывает срок, меняет статус и находит просроченные записи.

## Что работает сейчас

* общий layout с навигацией (React Router) и заметкой о временном хранении данных;
* общий список задач в состоянии `App` (`useState`); начальные данные берутся из `data/tasks.ts`;
* **создание** задачи (`/tasks/new`), **просмотр** (`/tasks/:id`), **редактирование** (`/tasks/:id/edit`) и **удаление** с подтверждением (`window.confirm`);
* одна переиспользуемая форма `TaskForm` с отдельным черновиком: «Отмена» ничего не сохраняет;
* проверка ввода: название 3–100 символов (пробелы обрезаются), обязательный срок; предметное правило — у задачи со статусом «Готово» должно быть описание результата (просроченный срок допустим);
* фильтр списка по статусу и кнопка «Сбросить фильтр»; различаются пустой список и отсутствие совпадений;
* страницы для неизвестного адреса и отсутствующей задачи;
* **тег задачи выбирается из справочника, загруженного по HTTP** (`GET /demo/tags.json`), с состояниями загрузки, ошибки и пустого результата, кнопкой «Повторить» и запретом сохранения без допустимого тега;
* строгая проверка типов TypeScript (`strict`) и production-сборка.

## Справочник тегов (ЛР 4)

Источник справочника — статический файл `frontend/public/demo/tags.json`. Vite раздаёт его по адресу `/demo/tags.json` (папка `public` в URL не пишется); в Network виден отдельный `GET`-запрос. Файл не импортируется в TypeScript и доступен посетителям, поэтому содержит только учебные значения. Формат элемента: `{ "id": "study", "name": "Учёба" }`, где `id` — постоянный код, `name` — название для пользователя.

| Файл | Назначение |
|---|---|
| `public/demo/tags.json` | справочник тегов (5 значений) |
| `src/types/tag.ts` | тип `Tag` |
| `src/services/tags.ts` | `getTags` (fetch, проверка `response.ok`), `parseTags` (проверка структуры и уникальности `id` во время выполнения) |
| `src/hooks/useTags.ts` | состояние загрузки `loading` / `error` / `success`, повторная попытка, отмена через `AbortController` |
| `src/components/TaskForm.tsx` | `select` тега, сообщения о состоянии, блокировка сохранения |

В `Task.tag` хранится **`id`** тега (например, `study`), в форме показывается `name` («Учёба»). Если сохранённый `id` не найден в справочнике, форма показывает сообщение и не подставляет другой тег автоматически. Недоступность справочника блокирует только сохранение формы; просмотр списка, переходы, отмена и удаление работают. Повтор запроса не сбрасывает введённый черновик.

## Ограничение: данные только в памяти

Основные записи (задачи) по-прежнему живут в состоянии компонента `App`; по сети загружается только справочник тегов. Внутренние переходы между страницами изменения сохраняют, но **после обновления страницы или перезапуска приложения возвращаются демонстрационные записи** из `frontend/src/data/tasks.ts`. Постоянное хранение и перенос справочника в Supabase будут добавлены в следующих работах; `localStorage` не используется.

## Текущие ограничения

Отсутствуют Supabase, авторизация и Node API; задачи не сохраняются между перезагрузками. Справочник берётся из статического JSON проекта, а не из базы данных.

## Использование ИИ

ИИ использовался для объяснения структуры React-проекта, проверки соответствия проекта требованиям лабораторной работы и поиска возможных ошибок. Предложенные изменения были проверены вручную по содержимому проекта, запуску и сборке.
